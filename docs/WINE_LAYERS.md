# Wine on RockOS — layered port plan

Wine cannot land in one step on a freestanding, no-libc kernel. This
roadmap adds it layer by layer, each layer independently buildable and
testable, with the whole build staying green in CI after every merge.

| # | Layer | What it gives Wine | Status |
|---|-------|--------------------|--------|
| 0 | User memory + syscall surface | `mmap`/`brk`/`munmap`, read/write, PID/sleep syscalls plus a userspace assembly test program exercising them | **in progress (this PR)** |
| 1 | Executable loader + launch | **PE32/PE32+ (`.exe`) parser + mapping into a ring-3 address space, entry launch, POSIX-shaped syscalls (read/write fds via RockFS, hints in mmap, fork/clone)** — start with a Win32-API-free (pure) PE, then imports via kernel32/Wine | **parser landed (host-verified), mapping+launch next** |
| 2 | libc for userspace | link a freestanding-friendly libc (musl, built with `--target=rockos`) into ring-3 executables | planned |
| 3 | Process model hardening | real per-process FPU/SSE state, argument passing on stack, environment block, PID table, dynamic loader (`ld-so` analog) | planned |
| 4 | Winelib toolchain | build Wine itself against layer 2/3 (Wine64 + Wow64 32-bit sub-arch = runs Win32 binaries) | planned |
| 5 | Windowing bridge | project Wine's `user32`/`gdi32` output onto RockOS desktop shell | planned |
| 6 | Drivers + perf | audio mapping, GPU blit path beyond the framebuffer, faster PMM beyond the current 1 GiB map limit | planned |

## Layer 1 landing order (per "we need this to run exes")

- **1a (this change):** `include/pe.h` / `src/kernel/pe.c` parse DOS+COFF
- OptionalHeader, section table, characteristics (`.text` exec / `.data`
- rw), and entry-point RVA for both PE32 (i386) and PE32+ (AMD64) images.
- Host-verified with `tests/pe_host_test.c`: a synthetic PE32, a
- synthetic PE32+ with two sections, plus rejection cases (bad magic,
- bad machine, too many sections, missing optional header, section
- bytes out of range). All PASS on the host gcc build.
- **1b (this change):** kernel mapping + launch. `runexe <path>` and
  `runexe builtin` stage the single section, map it at ImageBase
  + section RVA on a fresh code page (stack at the standard user stack
  region), and enter ring 3 through the layer 0 syscall surface. The
  1b envelope (machine matches the kernel, ImageBase 0x60000000, one
  section <=4KiB, no imports) is enforced by `pe_run_can_load`, and
  the import-free sample exe (`pe_sample32.h`, generated by
  `tools/make_pe32.py`) prints `E` and exits. Host-verified with
  `tests/pe_run_host_test.c`: parse + envelope acceptance plus 5
  rejections (wrong machine, ImageBase mismatch, multi-section,
  entry outside the section, oversized section).
- **1c after:** import table resolution into a Win32 API surface
- (kernel32 first: `VirtualAlloc`, `ExitProcess`, `WriteFile`,
- `GetStdHandle`/console) so regular Win32 exes run. Only import-free
- (hardcoded, no CRT) small exes run in step 1a/1b.

## Layer 0 details

- Syscall numbers (int 0x80): 0 exit, 1 putchar, 5 mmap, 6 munmap.
  Argument in RDI (64-bit for mmap/munmap, ASCII byte for putchar).
- `mmap` hands out fresh 4 KiB pages from the physical allocator and
  maps them USER|RW into the current address space at a kernel-chosen
  base above the test program's code/stack region; returns the virtual
  address or `(uint64_t)-1` on failure.
- `munmap` unmaps+releases pages previously handed out by `mmap` only
  (mapping table tracked in-kernel), refusing foreign addresses.
- A new user-mode test program (`ring3_memory_program`) mmaps a page,
  writes `0x5A`, reads it back, prints `M` on success / `X` on
  mismatch, and exits — run from the boot sequence next to the
  existing ring-3 test.

## Layer 1 addition: RockOS native executables (.rok)

Native executables live next to Wine in the same layer: the same user
syscall surface (int 0x80 exit/putchar/mmap/munmap), a smaller loader.

- File layout: magic "ROK1", 24-byte header (flags bit0 arch: 0=i386,
  1=amd64; entry offset; code size 24+4096 max).
- `include/rok.h` / `src/kernel/rok.c` parse and validate; host-verified
  with `tests/rok_host_test.c` (valid i386/amd64, bad magic/header,
  unknown flags, entry beyond code, oversized code, truncation,
  nonzero reserved bytes — all PASS).
- Shell: `run <path.rgo>`... `run <path>` (reads the .rok from RockFS,
  arch-gates the payload against the running kernel) and
  `run builtin` (self-contained demo that prints "R" via putchar and
  exits). Executed in ring 3 by `ring3_rok_task` at dedicated code and
  stack addresses.

## Layer 1c addition: base relocations (multi-section PE loads)

The layer-1b envelope was widened: any ImageBase, up to 16 sections,
SizeOfImage up to 256 KiB, machine matching the running kernel, no
imports (kernel32 still next). New `pe.c` pieces, all host-verified:

- `pe_image_t` now carries the optional-header data directories
  (NumberOfRvaAndSizes at offset 92 for PE32 / 108 for PE32+, entries
  from offset 96 / 112).
- `pe_rva_sourced` resolves an RVA (headers region or file-backed
  section) to a file offset and validates the byte count.
- `pe_image_snapshot` builds the runtime memory image (headers raw,
  sections at their RVAs, rest zero-filled).
- `pe_relocate` walks the relocation table and applies type
  0 (padding), 3 (PE32 HIGHLOW), 10 (PE32+ DIR64) fixups with
  `delta = RING3_PE_BASE - ImageBase`; delta 0 is idempotent, images
  with a nonzero fixup set are refused only when delta would corrupt
  bounds.
- `ring3_pe_task` maps every snapshot page at RING3_PE_BASE and tears
  down all session pages (plus the stack) on exit or fault; paths use
  per-session code/stack VAs instead of hardcoded test addresses.
- New fixture generator `tools/make_pe_reloc32.py` emits
  `src/kernel/pe_reloc32.h`: one-section .text at RVA 0x1000,
  ImageBase 0x400000, last-WORD image pointer 0x400110 at RVA 0x10F0
  fixed to 0x60000110, one HIGHLOW entry block at RVA 0x1080.
- `tests/pe_run_host_test.c` now covers parse + envelope (1c form) +
  snapshot + rva lookup + relocation (all PASS: 27 checks).

## Layer 1d addition: a first kernel32 import surface

The envelope now admits PE images with an import table, subject to a
single-DLL surface, and the loader replaces real imports with our own
int 0x80 trampolines - .exe bytes run against RockOS's kernel32:

- `pe_image_t` carries the parsed import surface: `import_rva` (the
  FirstThunk/IAT base), `import_count`, lowercased `import_dll`
  (16 bytes max), and `import_names` (up to `PE_IMPORT_MAX` = 16, 24
  bytes each). Parsing walks the data-directory-1 descriptor, refuses
  ordinals, second DLLs, and names that do not resolve to file-backed
  bytes (mid-parse uses the new internal `pe_rva_sourced_raw`; the
  public `pe_rva_sourced` still requires a fully valid image).
- Supported DLL: `kernel32.dll` only (case-insensitive). Supported
  functions (ids 0..3): ExitProcess, GetStdHandle, WriteFile,
  WriteConsoleA. Anything else is refused at envelope time.
- `pe_run_prepare_imports` appends one trampoline per import into the
  extra page after SizeOfImage (16-byte aligned) and patches each IAT
  entry in the snapshot with the stub's RVA. Stubs enter
  `RING3_SYSCALL_WIN32` (int 0x80, eax=7):
  - i386: stdcall args [esp+4..16] -> ESI/EDX/ECX/EDI, fn id in EBX,
    `ret imm16` pops the args.
  - AMD64: Win64 RCX,RDX,R8,R9 shuffled to RSI,RDX,RCX,R8, fn id in
    EDI.
- `ring3_win32_dispatch` serves them: ExitProcess reuses the exit
  cleanup; GetStdHandle answers 1 (stdout); WriteFile/WriteConsoleA
  print up to 256 validated user bytes and return the count (the
  lpNumberOfBytesWritten out-pointer is not written in 1d).
- The runtime import dispatch path is wired in `interrupt_dispatch`:
  rax == 7 with user CS routes fn + four frame arguments.
- New fixture `tools/make_pe_import32.py` emits
  `src/kernel/pe_import32.h`: PIC PE32 code that calls WriteFile via
  its IAT and ExitProcess, kernel32.dll with hint/name thunks.
- `tests/pe_run_host_test.c` covers import parsing (names, IAT RVA,
  case-folded DLL), stub bytes for both functions, IAT patching, and
  envelope/prepare refusals (unknown DLL, unknown fn, oversize list).
